// 01. the problem with RAG · RAG의 한계

Retrieval forgets. Wikis remember. 검색은 잊는다. 위키는 기억한다.
// Standard RAG · 표준 RAG

Stateless retrieval 상태 없는 검색

Upload docs → retrieve chunks at query time → generate answer. 문서 업로드 → 쿼리 시점에 청크 검색 → 답변 생성.

The LLM rediscovers the knowledge graph from scratch on every question. Nothing accumulates. LLM은 매 질문마다 지식 그래프를 처음부터 다시 발견한다. 아무것도 쌓이지 않는다.

// LLM Wiki · LLM 위키

Persistent compilation 영속적 컴파일

New source → LLM reads it, integrates into a markdown wiki: updates entity pages, revises summaries, flags contradictions. 새 소스 → LLM이 읽고 마크다운 위키에 통합: 엔티티 페이지 업데이트, 요약 수정, 모순 표시.

The wiki is a compounding artifact. 위키는 복리로 쌓이는 자산이다.

// 02. the core idea · 핵심 아이디어

Knowledge is compiled once and kept current—not re-derived on every query. 지식은 한 번 컴파일되고 최신으로 유지된다 — 매 쿼리마다 다시 도출하지 않는다.

You curate sources. You ask questions. The LLM does the bookkeeping: summarizing, cross-referencing, filing, reconciling contradictions across pages. 당신은 소스를 큐레이션하고, 질문을 던진다. LLM은 잡일을 한다: 요약, 상호 참조, 분류, 페이지 간 모순 정리.

> Obsidian is the IDE. The LLM is the programmer. The wiki is the codebase. > Obsidian은 IDE. LLM은 프로그래머. 위키는 코드베이스.

// 03. three layers · 세 개의 레이어

The stack. 스택 구조.
L1 / IMMUTABLE · 불변

Raw sources

원본 소스

Curated docs, articles, papers, images. The LLM reads but never modifies. Source of truth. 큐레이션된 문서, 기사, 논문, 이미지. LLM이 읽기만 하고 수정하지 않음. 진실의 원천.

read-only · 읽기 전용
L2 / GENERATED · 생성

The wiki

위키

LLM-generated markdown: entity pages, concept pages, summaries. The LLM owns this layer. You read; it writes. LLM이 생성한 마크다운: 엔티티/개념 페이지, 요약. LLM이 이 레이어를 소유. 사람은 읽고, LLM이 쓴다.

read + write (LLM) · LLM이 쓰기
L3 / CONFIG · 설정

The schema

스키마

CLAUDE.md / AGENTS.md. Structure, conventions, workflows. Co-evolved over time. CLAUDE.md / AGENTS.md. 구조·컨벤션·워크플로우. 시간이 지나며 함께 진화.

human + LLM · 사람 + LLM
raw/ ───→ [ schema ] ───→ wiki/

// 04. three verbs · 세 개의 동사

How you work the wiki. 위키를 다루는 방식.
verb_01

Ingest

적재

Drop a source in raw/. The LLM reads, discusses takeaways, writes a summary, updates the index, touches 10–15 related pages, appends to the log. raw/에 소스를 놓는다. LLM이 읽고, 시사점을 논의하고, 요약을 작성하고, 인덱스를 업데이트하고, 관련 페이지 10~15개를 손보고, 로그에 추가한다.

verb_02

Query

쿼리

Ask questions. Answers come as pages, tables, slide decks, charts. Good answers get filed back. 질문을 던진다. 답변은 페이지·표·슬라이드·차트로 나온다. 좋은 답변은 다시 위키에 정리해 넣는다.

verb_03

Lint

린트

Periodic health checks. Find contradictions, stale claims, orphan pages, missing cross-refs. 주기적 건강 검진. 모순, 오래된 주장, 고아 페이지, 누락된 상호 참조를 찾는다.

> A single ingest can touch ~15 pages. Humans abandon wikis at this maintenance cost. LLMs don't. > 한 번의 적재로 페이지 15개가 바뀐다. 사람은 이 유지비용에 위키를 포기한다. LLM은 안 한다.

// 05. two special files · 두 개의 특수 파일

index.md & log.md 콘텐츠 카탈로그와 시간순 기록.
index.md
# Wiki Index ## Entities - [[Vannevar Bush]] — Memex inventor - [[Tolkien Gateway]] — fan-wiki ref ## Concepts - [[Compounding artifacts]] - [[Persistent retrieval]] ## Sources - [[src-001-memex-1945]] ...

// content-oriented · 콘텐츠 지향 Catalog of every page. Read first when answering — drill in from there. Works at hundreds of pages without embeddings. 모든 페이지의 카탈로그. 답변할 때 먼저 읽고 그 다음 들어간다. 수백 페이지 규모까지 임베딩 없이 작동.

log.md
## [2026-04-02] ingest | Memex paper (Bush, 1945) → updated 12 pages ## [2026-04-03] query | compare RAG vs wiki → filed as new page ## [2026-04-05] lint | 3 orphans, 2 contradictions ...

// chronological · 시간순 Append-only timeline. Consistent prefixes make it grep-able: grep "^## \[" log.md | tail 추가 전용 타임라인. 일관된 접두사 덕에 grep 가능: grep "^## \[" log.md | tail

// 06. where this fits · 어디에 맞는가

Anywhere knowledge accumulates. 지식이 쌓이는 모든 곳.
[01]
Personal
개인용

Goals, journaling, self-tracking. 목표, 일기, 자기 추적.

[02]
Research
연구

Months on a topic. Papers in, evolving thesis out. 한 주제를 몇 달간. 논문 입력, 진화하는 논지 출력.

[03]
Reading a book
책 읽기

File chapters as you go. End up with a personal companion wiki. 읽으며 챕터를 정리. 개인 동반 위키 완성.

[04]
Team / business
팀 / 비즈니스

Internal wiki fed by Slack, meetings, calls. Stays current. Slack·회의·통화로 피딩되는 사내 위키. 항상 최신.

[05]
Due diligence
실사 / 분석

Competitive analysis, investment research. Every doc compounds. 경쟁 분석, 투자 리서치. 모든 문서가 복리로.

[06]
Anything that grows
자라나는 모든 것

Course notes, hobby deep-dives, trip planning. 강의 노트, 취미 심화, 여행 계획.

// 07. why this works · 왜 작동하는가

~0 marginal cost of maintenance 유지보수의 한계 비용

The tedium isn't reading. It's bookkeeping.

지루한 건 읽기가 아니다. 잡일 처리다.

Updating cross-refs. Keeping summaries current. Noting contradictions across dozens of pages. 상호 참조 업데이트. 요약 최신화. 수십 페이지에 걸친 모순 표시.

Humans abandon wikis when maintenance cost outpaces value.
LLMs don't get bored. 사람은 유지비용이 가치를 추월하면 위키를 포기한다.
LLM은 지루해하지 않는다.

● TAKEAWAYS · 핵심 정리 llm-wiki-pattern

// 09. tl;dr · 한 줄 요약

What to remember. 기억할 것들.
  1. RAG retrieves. Wikis accumulate. RAG는 검색하고, 위키는 쌓는다. Stop re-deriving knowledge. Compile once, keep current. 지식을 매번 다시 도출하지 마라. 한 번 컴파일하고 최신으로 유지하라.
  2. The LLM owns the wiki layer. 위키 레이어는 LLM의 것이다. You curate sources and ask questions. The LLM writes, links, lints. 사람은 소스를 큐레이션하고 질문한다. LLM은 쓰고, 잇고, 점검한다.
  3. Three verbs: ingest, query, lint. 세 동사: 적재 · 쿼리 · 린트. Good answers file themselves back — explorations compound. 좋은 답변은 위키에 다시 정리된다 — 탐구도 복리로 쌓인다.
  4. It's just markdown in a git repo. 결국 git 저장소의 마크다운일 뿐. Version control, branching, diffing — for free. Tools are optional. 버전 관리·브랜칭·diff — 공짜. 도구는 선택사항.

> Pattern, not product. Hand this idea to your agent and instantiate your own. > 제품이 아니라 패턴. 에이전트에게 넘기고, 당신만의 버전을 만들어라.
