# 에이전트(Agent)란? — 클로드 코드의 일꾼
> 원본: claude_agent.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
에이전트는 "지시를 받고, 도구를 골라 쓰고, 스스로 일을 끝내는 AI 일꾼"이며, 클로드 코드 자체가 하나의 에이전트다.

## 이게 뭐예요?
에이전트는 회사의 **신입사원**에 비유할 수 있어요.
사원은 업무 지시(instructions)를 받고, 회사 규칙(system prompt)을 따르고, 회사가 준 장비(tools)를 쓰고, 자기 책상 위의 서류(context)만 볼 수 있죠.
여러분이 클로드 코드에 말을 걸면, 이 "사원"이 요청을 해석하고 → 어떤 도구를 쓸지 정하고 → 실행하고 → 결과를 보고합니다.
혼자 다 못 하면 전문 분야의 다른 사원(서브에이전트)에게 일을 나눠주기도 해요.

## 핵심 정리
- 공식처럼 기억하기: **Agent = Model(두뇌) + Instructions(지시) + Tools(도구) + Context(작업 기억)**
- 에이전트가 하는 일: 요청 해석 → 도구 선택 → 실행 → 결과 반환
- 할 수 있는 것: 파일 읽기, 코드 수정, 코드베이스 검색, 명령 실행, 작업 계획, 서브에이전트에게 위임
- **메인 에이전트**: 여러분이 직접 대화하는 기본 클로드. 전체 책임을 지고 일을 나눠줄 수 있다
- **서브에이전트**: 특정 일만 하는 전문가. 별도의 컨텍스트 윈도우(작업 기억 공간)에서 일하고 결과만 메인에게 보고
- 이 구조 덕분에: 역할 분리, 기억 공간 절약, 도구 권한 통제, 여러 작업 동시 진행이 가능하다

## 따라해보기
1. 터미널에서 `claude` 입력
   - 클로드 코드(메인 에이전트)를 실행한다.
2. "이 폴더에 어떤 파일이 있는지 알려줘" 라고 입력
   - 에이전트가 스스로 도구(파일 목록 보기)를 골라 실행하는 과정을 관찰한다.
3. "방금 네가 어떤 도구를 썼는지 설명해줘" 라고 입력
   - 에이전트의 "해석 → 도구 선택 → 실행 → 보고" 흐름을 직접 확인한다.

## 주의할 점 / 자주 헷갈리는 것
- "에이전트 = 챗봇"이 아니다. 챗봇은 말만 하지만, 에이전트는 도구를 써서 실제 행동을 한다.
- 컨텍스트 윈도우(작업 기억)는 무한하지 않다. 대화가 너무 길어지면 앞 내용을 잊을 수 있다.
- 메인 에이전트와 서브에이전트는 기억을 공유하지 않는다. 서브에이전트는 결과 보고서만 돌려준다.
- 에이전트가 "자율적으로" 일한다고 해서 다 맡겨두면 안 된다. 중요한 작업은 사람이 확인하자.
