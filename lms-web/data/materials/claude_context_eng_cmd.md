# 컨텍스트 관리 3총사 — /context, /clear, /compact
> 원본: claude_context_eng_cmd.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
`/context`로 클로드의 머릿속을 들여다보고, 지저분하면 `/clear`(전부 비우기) 또는 `/compact`(요약해서 줄이기)로 정리한다.

## 이게 뭐예요?
클로드의 머릿속(컨텍스트 창)은 **책상**과 같습니다. 작업할수록 서류(대화 기록, 읽은 파일, 로그)가 쌓이고, 책상이 꽉 차면 일을 못 하거나 엉뚱한 서류를 보고 답하게 됩니다. `/context`는 책상 위에 뭐가 얼마나 쌓였는지 보는 CCTV, `/clear`는 책상을 싹 치우는 것, `/compact`는 서류를 버리는 대신 한 장짜리 요약본으로 바꿔 책상을 넓히는 것입니다.

## 핵심 정리
- `/context`: 현재 모델 이름, 컨텍스트 창 크기, 토큰(token, 모델이 글을 세는 단위) 사용량을 항목별(시스템 프롬프트/도구/메모리/대화 등)로 보여준다. 일종의 **관찰 도구**.
- 컨텍스트가 옛 로그, 긴 에러 메시지로 오염되면 클로드는 "잘못된 세계" 안에서 추론한다 → 답이 나빠지는 주원인.
- `/clear`: 대화 기록을 전부 삭제하고 0에서 시작. 단, **파일·코드·저장소는 그대로**다. 지워지는 건 대화 기억뿐.
- `/clear` 쓰는 때: 클로드가 잘못된 방향에 갇혔을 때, 대화가 너무 지저분할 때, 전혀 다른 주제로 넘어갈 때.
- `/compact`: 대화 기록을 삭제하지 않고 **짧은 요약으로 다시 쓰기**. 중요한 맥락은 유지하면서 토큰을 확보한다.
- `/compact` 쓰는 때: 긴 디버깅 세션, 큰 로그를 읽은 직후, 다음 큰 작업 시작 전.
- 한도(약 20만 토큰)에 가까워지면 클로드가 알아서 자동 요약(auto-compact)하지만, 어떻게 요약될지 예측이 어렵다. 직접 `/compact`하면 내가 압축 시점을 통제할 수 있다.
- 초보와 숙련자의 차이: 초보는 다 자동에 맡기고, 숙련자는 컨텍스트를 **모니터링하고 의도적으로 정리**한다.

## 따라해보기
1. 클로드 코드에서 입력:
   ```
   /context
   ```
   → 지금 토큰을 얼마나 썼는지, 무엇이 차지하는지 확인한다.
2. 대화가 길어졌다면:
   ```
   /compact
   ```
   → 대화가 요약본으로 압축되고 여유 공간이 늘어난다. 다시 `/context`로 전후를 비교해보자.
3. 완전히 새 주제로 시작하고 싶을 때:
   ```
   /clear
   ```
   → 대화 기록이 전부 사라지고 새 세션처럼 시작한다.

## 주의할 점 / 자주 헷갈리는 것
- `/clear`는 **코드나 파일을 지우지 않는다.** 대화 기억만 지운다. (반대로, 지운 대화는 복구 안 됨)
- `/clear` vs `/compact`: 전부 버리기 vs 요약해서 남기기. 맥락이 아직 필요하면 `/compact`를 쓰자.
- `/context`는 보기만 하는 명령이라 자주 눌러도 아무 부작용이 없다. 습관처럼 확인하자.
- 자동 요약만 믿으면 중요한 맥락이 예고 없이 뭉개질 수 있다. 큰 작업 전에 직접 `/compact` 하는 게 안전.
