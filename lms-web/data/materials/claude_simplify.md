# /simplify — 작업 끝낸 코드를 깔끔하게 다듬기
> 원본: claude_simplify.pdf · 난이도: ★★☆(곧 필요)

## 한 줄 요약
`/simplify`는 방금 고친 코드를 검토해서 중복·지저분함·비효율을 찾아내고, 직접 고쳐 주는 "마무리 청소" 명령이다.

## 이게 뭐예요?
요리를 마친 뒤 주방을 정리하는 것과 같아요. 음식(기능)은 완성됐지만 싱크대엔 그릇이 쌓여 있죠.
`/simplify`는 클로드가 **최근에 변경된 파일들**을 다시 살펴보면서
"같은 코드가 두 번 있네", "이건 더 읽기 쉽게 쓸 수 있네", "여긴 쓸데없이 느리네" 하는 부분을 찾아요.
그리고 제안만 하는 게 아니라 실제로 코드를 고쳐서 정리까지 끝내 줍니다.

## 핵심 정리
- `/simplify`는 **변경 후 정리(post-change cleanup)** 명령 — 새 기능을 만드는 게 아니라 만든 것을 다듬는다.
- 검사하는 3가지:
  - **코드 재사용**: 중복 로직(똑같은 코드가 여러 곳에 복사된 것) 제거
  - **코드 품질**: 읽기 쉬움, 구조, 유지보수성(나중에 고치기 쉬운 정도)
  - **효율**: 불필요한 작업, 성능을 깎아먹는 패턴
- 내부 동작: 검토 담당 에이전트(보조 AI 일꾼) 3명을 동시에 풀어서 각자 검토 → 결과 합치기 → 중요한 것부터 직접 수정.
- 쓰는 타이밍: 기능 완성 후, 버그 수정 후, PR(코드 제출) 올리기 전 — "다 했다! 이제 깨끗하게" 시점.
- 뒤에 한 줄 덧붙여 관심사를 지정할 수 있다(focus 모드). 예: `/simplify focus on memory efficiency`.
- 버그를 찾는 명령이 아니다. 버그 검사는 `/code-review`가 담당 — 나중에 배워요.

## 따라해보기
1. 기본 정리 (클로드 코드에서 뭔가 만들거나 고친 직후에)
   ```
   /simplify
   ```
   → 최근 변경된 파일들을 검토하고 알아서 다듬어 줘요.
2. 중복 제거와 가독성에 집중시키기
   ```
   /simplify focus on removing duplication and improving readability
   ```
   → 검토자들이 "중복"과 "읽기 쉬움" 위주로 살펴봐요.
3. 정리 후 무엇이 바뀌었는지 물어보기
   ```
   방금 simplify에서 뭘 고쳤는지 초보자 눈높이로 설명해줘
   ```
   → 바뀐 내용을 복습하면 코드 공부도 됩니다.

## 주의할 점 / 자주 헷갈리는 것
- `/simplify`는 코드를 **실제로 수정**해요. 실행 전에 지금 상태를 git에 저장(커밋)해 두면 안심이에요.
- "최근 변경된 코드"가 대상이라, 아무것도 안 고친 상태에서 돌리면 할 일이 거의 없어요.
- 동작이 바뀌는 게 아니라 모양이 깔끔해지는 거예요. 정리 후에도 프로그램은 똑같이 동작해야 정상입니다.
- 버그 찾기용이 아니에요. "코드가 이상하게 동작해요"라면 simplify가 아니라 디버깅을 해야 해요.
