# 클로드 코드의 메모리(Memory) 이해하기
> 원본: claude_memory.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
메모리는 클로드가 세션이 끝나도 "나에 대해 기억하는 것"이고, `/memory` 명령으로 확인·관리할 수 있다.

## 이게 뭐예요?
클로드 코드는 기본적으로 대화가 끝나면 그 내용을 잊어버립니다. 그래서 매번 "나는 이런 사람이고, 이런 프로젝트를 해요"라고 다시 설명해야 하죠. 메모리는 이 문제를 해결하는 **수첩** 같은 기능입니다. 친한 단골 카페 사장님이 내 취향("아이스 아메리카노, 샷 추가")을 수첩에 적어두면 매번 말 안 해도 되는 것처럼, 클로드도 내 역할·선호·프로젝트 정보를 파일로 저장해두고 다음 대화에서 자동으로 참고합니다.

## 핵심 정리
- 메모리 = **세션(한 번의 대화)이 끝나도 유지되는 저장된 정보**. 단순 대화 기록(채팅 히스토리)이 아니다.
- 세션 컨텍스트(context, 지금 대화에서 임시로 기억 중인 내용)는 대화가 끝나면 사라지지만, 메모리는 남는다.
- `/memory` 명령으로 저장된 메모리를 보고 편집할 수 있다. "나에 대한 지식 베이스"라고 생각하면 된다.
- 비유: `/context`는 RAM(껐다 켜면 사라짐), `/memory`는 SSD(저장됨).
- 저장하면 좋은 것: 내 역할, 자주 쓰는 기술, 코딩 스타일, 프로젝트 규칙처럼 **잘 안 바뀌는 정보**.
- 저장하면 안 되는 것: 일회성 질문, 임시 디버깅 상태, 비밀번호·API 키 같은 민감 정보.
- 메모리는 시스템 프롬프트(클로드에게 미리 주어지는 지시문)에 자동으로 끼워 넣어져 답변의 말투·깊이·가정에 영향을 준다.

## 따라해보기
1. 클로드 코드 실행 후 입력:
   ```
   /memory
   ```
   → 지금 저장된 User memory(전체 공통)와 Project memory(이 폴더 전용)를 보여준다.
2. 클로드에게 이렇게 말해보기:
   ```
   앞으로 기억해줘: 나는 프로그래밍 입문자라서 설명은 항상 쉬운 한국어로 해줘.
   ```
   → 클로드가 이 선호를 메모리에 저장하고 다음 세션부터 적용한다.
3. 새 터미널에서 클로드 코드를 다시 켜고 아무 질문이나 해보기 → 저장한 선호가 반영되는지 확인.

## 주의할 점 / 자주 헷갈리는 것
- **메모리 ≠ 채팅 기록.** 지난 대화 전체를 기억하는 게 아니라, 골라서 저장한 "구조화된 정보"만 기억한다.
- 비밀번호, API 키 같은 민감한 정보는 절대 메모리에 저장하지 말 것.
- `/context`(지금 대화 상태 보기)와 `/memory`(영구 저장 정보 보기)를 헷갈리기 쉽다.
- 메모리에 잘못된 정보가 쌓이면 계속 엉뚱한 답이 나온다. 가끔 `/memory`로 열어 정리해주자.
