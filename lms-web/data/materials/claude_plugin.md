# 플러그인(Plugins) — 기능을 묶어서 나눠 쓰는 "확장팩"
> 원본: claude_plugin.pdf · 난이도: ★★★(나중에)

## 한 줄 요약
플러그인은 스킬·훅·에이전트 같은 클로드 코드 확장 기능을 한 상자에 담아, 다른 사람·다른 프로젝트와 공유하는 패키지다.

## 이게 뭐예요?
스마트폰의 "앱"을 떠올리면 쉬워요. 앱 하나를 설치하면 여러 기능이 한꺼번에 따라오죠.
플러그인도 마찬가지로, 스킬·명령어·훅 등을 한 폴더에 묶어 둔 설치형 꾸러미예요.
내 컴퓨터에서만 쓰던 설정(스탠드얼론)과 달리, 플러그인은 버전을 매겨 팀원과 공유하거나
마켓플레이스(플러그인 장터)에서 내려받아 쓸 수 있어요.

## 핵심 정리
- 플러그인 = 클로드 코드에 **재사용 가능한 기능 묶음**(스킬, 에이전트, 훅, MCP 서버 등)을 더하는 패키지.
- 개인 실험은 그냥 `.claude/` 폴더 설정(스탠드얼론)으로 충분하고, **공유·재사용**이 필요할 때 플러그인으로 만든다.
- 플러그인 명령은 이름이 붙는다: `/plugin-name:skill` 처럼 "어느 플러그인의 기능인지"가 표시됨.
- 기본 폴더 구조:
  - `.claude-plugin/plugin.json` → 매니페스트(이름·버전·설명을 적는 신분증 파일)
  - `commands/` 슬래시 명령 · `skills/` 스킬 · `agents/` 에이전트 · `hooks/` 자동화
- 만들기 4단계: 폴더 생성 → plugin.json 작성 → skills/에 SKILL.md 추가 → `claude --plugin-dir`로 테스트.
- 잘 만든 플러그인은 README와 버전 번호를 붙여 마켓플레이스에 공개할 수 있다.
- 이미 쓰던 `.claude/` 설정을 플러그인으로 옮기는 것도 가능 (파일 복사 + 매니페스트 작성).
- MCP/LSP 연동 같은 고급 구성은 나중에 배워요.

## 따라해보기
1. 지금 설치된 플러그인 구경하기 (클로드 코드 안에서)
   ```
   /plugin
   ```
   → 플러그인 관리 화면이 열려요. 설치/끄기/켜기를 여기서 해요.
2. 연습용 플러그인 뼈대 만들기 (터미널에서)
   ```
   mkdir -p my-first-plugin/.claude-plugin my-first-plugin/skills
   ```
   → 플러그인 폴더와 필수 하위 폴더를 만들어요. plugin.json은 클로드에게 만들어 달라고 해도 돼요.
3. 내 플러그인을 붙여서 클로드 코드 실행하기
   ```
   claude --plugin-dir ./my-first-plugin
   ```
   → 이 폴더를 플러그인으로 읽어 들인 상태로 클로드 코드가 켜져요. 테스트용으로 씁니다.

## 주의할 점 / 자주 헷갈리는 것
- 스킬 하나만 필요하면 플러그인까지 갈 필요 없어요. 플러그인은 "묶어서 공유"가 목적입니다.
- `commands/`, `skills/` 폴더는 `.claude-plugin/` **안이 아니라 옆에**(플러그인 최상위) 둬야 해요. 자주 틀리는 부분!
- 플러그인 명령은 `/이름:기능` 형식이라, 그냥 `/기능`으로 치면 못 찾을 수 있어요.
- 남이 만든 플러그인은 설치 전에 어떤 훅·명령이 들어 있는지 설명을 한번 읽어 보세요.
