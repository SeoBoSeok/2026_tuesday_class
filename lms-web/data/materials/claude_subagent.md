# 서브에이전트 — 전문 분야 보조 일꾼 만들기
> 원본: claude_subagent.pdf · 난이도: ★★☆(곧 필요)

## 한 줄 요약
서브에이전트는 특정 작업(코드 리뷰, 검색 등)만 전담하는 보조 AI로, 메인 대화의 기억 공간을 아끼면서 일을 나눠 처리하게 해준다.

## 이게 뭐예요?
병원에 가면 접수처(메인 에이전트)가 있고, 증상에 따라 안과·피부과 같은 **전문의(서브에이전트)** 에게 보내주죠.
클로드 코드도 똑같아요. 메인 클로드가 "이건 코드 리뷰 일이네" 하고 판단하면, 코드 리뷰 전문 서브에이전트에게 자동으로 넘깁니다.
전문의는 자기 진료실(별도 컨텍스트)에서 일하고, 진단 결과만 접수처로 돌려보내요.
덕분에 메인 대화는 깔끔하게 유지되고, 각 전문가는 자기 일에만 집중할 수 있습니다.

## 핵심 정리
- 서브에이전트마다 자기만의 것이 있다: 시스템 프롬프트(역할 지시), 도구 접근 권한, 독립된 컨텍스트 윈도우
- 왜 쓰나?
  - **컨텍스트 보존**: 자료 조사 같은 긴 작업을 분리해 메인 대화를 깔끔하게
  - **제약 강제**: 읽기만 가능하게 하는 등 도구 제한 가능
  - **재사용**: 팀/프로젝트끼리 설정 공유
  - **비용 절약**: 간단한 일은 싼 모델(haiku)에게
- 기본 내장 서브에이전트: **Explore**(빠른 코드 검색, 읽기 전용), **Plan**(계획 중 조사), **general-purpose**(복잡한 다단계 작업)
- 만드는 법: YAML frontmatter(머리말)가 붙은 마크다운 파일, 또는 `/agents` 명령
  - 예: `name: code-reviewer`, `description: ...`, `tools: Read, Glob, Grep`, `model: sonnet`
- 클로드는 작업이 서브에이전트의 description과 맞으면 **자동으로 위임**한다
- 서브에이전트는 부모 대화의 스킬을 물려받지 않는다

## 따라해보기
1. 클로드 코드에서 `/agents` 입력
   - 사용 가능한 에이전트 목록을 보고, 새 서브에이전트를 만드는 메뉴로 들어간다.
2. `/agents`에서 "코드를 읽고 칭찬할 점과 고칠 점을 알려주는 리뷰어" 서브에이전트를 만들어보기
   - name, description, 도구(Read, Glob, Grep)를 고르는 과정을 체험한다.
3. "방금 만든 code-reviewer로 이 파일을 리뷰해줘" 라고 입력
   - 메인 에이전트가 서브에이전트에게 일을 넘기고 결과를 받아오는 걸 관찰한다.

## 주의할 점 / 자주 헷갈리는 것
- description을 대충 쓰면 클로드가 언제 이 서브에이전트를 써야 할지 몰라서 자동 위임이 안 된다.
- 서브에이전트는 메인 대화 내용을 모른다. 필요한 정보는 작업 지시에 다 담겨야 한다.
- 도구를 너무 많이 주면 전문가의 의미가 없다. 리뷰어에겐 읽기 도구만 주는 식으로 최소한만.
- 메모리 설정(user/project/local), 훅(hook) 같은 고급 기능도 있지만 — 나중에 배워요.
