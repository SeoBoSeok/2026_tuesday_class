# 디버깅 옵션 — 클로드 코드 속을 들여다보는 법
> 원본: claude_debugging.pdf · 난이도: ★★★(나중에)

## 한 줄 요약
`--debug`, `--verbose`, `--debug-file` 옵션을 켜면 클로드 코드가 속으로 무슨 일을 하는지 기록으로 볼 수 있어, 문제가 생겼을 때 원인을 찾기 쉽다.

## 이게 뭐예요?
자동차 계기판에 경고등만 켜지면 뭐가 문제인지 모르지만, 정비소 진단기를 연결하면 상세 기록이 다 나오죠.
클로드 코드도 평소엔 API 호출, 훅 실행, 파일 읽기 같은 내부 작업을 전부 숨기고(블랙박스) 결과만 보여 줘요.
디버깅 옵션은 이 숨겨진 과정을 화면이나 파일에 기록해 주는 "진단기 모드"예요.
"훅을 만들었는데 왜 안 돌지?", "왜 이렇게 느리지?" 같은 상황에서 어디서 막혔는지 직접 확인할 수 있어요.

## 핵심 정리
- 클로드 코드는 기본 모드에서 내부 동작(API 호출, MCP 통신, 훅 실행, 파일 입출력)을 숨긴다.
- 뭔가 안 될 때는 디버그 플래그(실행 시 붙이는 옵션)로 "어디서 막혔는지"를 봐야 한다.
- 3가지 주요 옵션:
  - `--verbose`: 진행 과정을 턴(주고받는 단위)별로 자세히 출력
  - `--debug`: 내부 동작 추적. `claude --debug "api,hooks,mcp"`처럼 카테고리를 골라 볼 수 있음
  - `--debug-file <경로>`: 디버그 기록을 파일로 저장 (자동으로 --debug도 켜짐)
- `!` 붙이면 제외: `claude --debug "!statsig,!file"` = 그 항목들 빼고 다 보여줘.
- 훅, 플러그인, MCP 서버(외부 도구 연결 장치)를 직접 만들기 시작하면 거의 매일 쓰게 되는 도구다.
- 지금 단계에선 "문제 생기면 --debug를 켜 본다" 정도만 기억하면 충분해요. 세부 카테고리는 나중에 배워요.

## 따라해보기
1. 디버그 모드로 클로드 코드 켜기 (터미널에서)
   ```
   claude --debug
   ```
   → "Debug mode enabled"와 함께 기록 파일 위치가 표시돼요. 평소와 똑같이 쓰면 기록이 쌓여요.
2. 기록을 내가 정한 파일로 저장하기
   ```
   claude --debug-file /tmp/claude.log
   ```
   → 작업 후 /tmp/claude.log를 열어 보면(또는 클로드에게 읽어 달라고 하면) 내부 동작이 다 보여요.
3. 저장된 로그 구경하기
   ```
   tail -20 /tmp/claude.log
   ```
   → 로그 파일의 마지막 20줄을 보여 줘요. 무슨 기록이 남는지 감 잡기용.

## 주의할 점 / 자주 헷갈리는 것
- 디버깅 옵션은 클로드 코드를 **켤 때** 터미널에서 붙이는 옵션이에요. 채팅창에 치는 슬래시 명령이 아닙니다.
- 디버그 모드는 출력이 아주 많아요. 평소엔 끄고, 문제가 있을 때만 켜세요.
- 로그를 직접 다 읽을 필요 없어요. 로그 파일을 클로드에게 주면서 "왜 안 되는지 찾아줘"라고 해도 됩니다.
- `--verbose`(과정을 자세히)와 `--debug`(내부 동작 추적)는 용도가 달라요. 보통 문제 분석엔 --debug면 충분해요.
