# MCP vs Skill — 도구와 요령의 차이
> 원본: claude_mcp_skills.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
MCP는 클로드에게 "새 도구"를 주는 것이고, Skill은 클로드에게 "일 잘하는 요령(매뉴얼)"을 주는 것이다.

## 이게 뭐예요?
요리사를 떠올려 보세요. MCP는 요리사에게 오븐이나 믹서기 같은 **새 주방기구**를 사주는 것이고,
Skill은 요리사에게 **레시피 노트**를 주는 것이에요.
기구가 없으면 못 만드는 요리가 있고, 레시피가 없으면 맛이 들쭉날쭉하죠.
둘을 같이 쓰면(좋은 기구 + 좋은 레시피) 클로드가 가장 일을 잘하게 됩니다.

## 핵심 정리
- **MCP** = 외부 시스템 연결 (파일시스템, Git 저장소, 데이터베이스, API 등) → "클로드의 USB 포트"
- **Skill** = 재사용 가능한 행동 패턴/사고 템플릿 → "플레이북 + 본능"
  - 생각하는 순서, 제약 조건, 출력 형식, 모범 사례, 가드레일(안전 규칙)을 담는다
- Skill의 실체는 폴더 하나다:
  - `SKILL.md` (필수, 메인 지시문) + `template.md`, `examples/`, `scripts/` (선택)
- SKILL.md 맨 위에는 `name:`과 `description:`을 쓴다 (frontmatter, 파일 머리에 붙는 정보)
- 최고의 조합은 **MCP + Skill**: MCP로 진짜 데이터를 읽고, Skill로 전문가처럼 분석해서, 정해진 형식으로 결과를 낸다
- 비유: Skill은 재사용 디자인 패턴, MCP는 마이크로서비스 연동 — 지금은 "요령 vs 도구"로만 기억해도 충분

## 따라해보기
1. `mkdir -p ~/.claude/skills/my-skill`
   - 내 스킬을 담을 폴더를 만든다.
2. `ls ~/.claude/skills`
   - 내 컴퓨터에 설치된 스킬 폴더들을 확인한다.
3. 클로드 코드에서 "explain-code 같은 스킬 파일(SKILL.md) 예시를 만들어줘" 라고 요청
   - 클로드가 직접 SKILL.md 구조를 만들어 주는 걸 보면서 배운다.

## 주의할 점 / 자주 헷갈리는 것
- "기능이 안 돼요" → MCP(도구) 문제인지, "결과물 품질이 별로예요" → Skill(요령) 문제인지 구분하자.
- Skill은 코드를 실행하는 게 아니라 클로드의 행동을 안내하는 문서다 (scripts 폴더는 예외적으로 실행 가능).
- SKILL.md의 description이 모호하면 클로드가 언제 그 스킬을 써야 할지 모른다. 구체적으로 쓰기.
- MCP와 Skill 중 하나만 고르는 게 아니다. 보통 같이 쓸 때 가장 강력하다.
