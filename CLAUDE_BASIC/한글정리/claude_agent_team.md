# 에이전트 팀 — 여러 클로드가 협업하기
> 원본: claude_agent_team.pdf · 난이도: ★★★(나중에)

## 한 줄 요약
에이전트 팀은 여러 개의 클로드 코드 인스턴스가 역할을 나눠 갖고, 공유 작업 목록과 메시지로 서로 소통하며 함께 일하는 기능이다.

## 이게 뭐예요?
서브에이전트가 "사장님 한 명이 알바생에게 일 시키는" 구조라면, 에이전트 팀은 **진짜 회사 팀**에 가까워요.
팀장(메인 세션)이 팀을 꾸리고 할 일 목록(Task list)을 칠판에 붙이면, 팀원들이 알아서 일을 집어가고(claim), 서로 메시지(Mailbox)도 주고받죠.
한 명은 기획, 한 명은 구현, 한 명은 검토 — 이렇게 역할을 나눌 수 있어요.
대신 회의가 많아지는 만큼 비용(토큰)도 훨씬 많이 듭니다.

## 핵심 정리
- 구성 요소 4가지:
  - **Team lead**(팀장): 팀을 만들고 팀원을 띄우고 조율하는 메인 세션
  - **Teammates**(팀원): 각자 별도의 클로드 코드 인스턴스
  - **Task list**(공유 작업 목록): 팀원들이 가져가서(claim) 완료하는 할 일 목록
  - **Mailbox**(우편함): 에이전트끼리 직접 메시지를 주고받는 통로
- 서브에이전트와의 차이: 서브에이전트는 메인에게만 보고 / 팀원은 **서로 직접 소통 + 스스로 작업 분배**. 대신 토큰 비용이 훨씬 높다
- 이런 때 좋다: 여러 관점의 조사·리뷰, 서로 안 겹치는 새 모듈 개발, 경쟁 가설 디버깅(서로 다른 원인 추측을 동시 검증), 프론트+백엔드+테스트 동시 작업
- 실험적 기능이라 켜야 쓸 수 있다: 환경변수 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`
- 화면 모드 2가지: **In-process**(한 터미널 안, Shift+Down으로 팀원 전환) / **Split panes**(팀원마다 분할 창, tmux나 iTerm2 필요)
- 설정 파일 위치: 팀 설정 `~/.claude/teams/{팀이름}/config.json`, 작업 목록 `~/.claude/tasks/{팀이름}/`

## 따라해보기
1. `export CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`
   - 에이전트 팀 기능을 켠다(현재 터미널에서만 유효).
2. `claude --teammate-mode in-process`
   - 팀원들이 내 터미널 안에서 돌아가는 모드로 클로드 코드를 실행한다.
3. 클로드 코드에서 다음처럼 요청해보기:
   "TODO 주석 추적 CLI 도구를 설계 중이야. 에이전트 팀을 만들어서 한 명은 UX, 한 명은 기술 구조, 한 명은 반대 의견 담당으로 검토해줘"
   - 팀이 만들어지고 역할별로 토론하는 과정을 관찰한다.

## 주의할 점 / 자주 헷갈리는 것
- **토큰을 정말 많이 쓴다.** 단순한 작업은 그냥 혼자(단일 세션) 시키는 게 낫다.
- 서브에이전트 vs 팀 헷갈리지 말기: "결과만 받으면 됨" → 서브에이전트 / "팀원끼리 소통·협업 필요" → 팀.
- 실험적(experimental) 기능이라 동작이 바뀔 수 있고, 환경변수를 안 켜면 아예 안 보인다.
- Split panes 모드는 tmux 또는 iTerm2 설치/설정이 필요하다. 처음엔 in-process로 충분하다.
