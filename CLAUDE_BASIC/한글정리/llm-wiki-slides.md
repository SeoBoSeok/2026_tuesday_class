# LLM 위키 패턴 — AI가 관리해주는 나만의 지식 창고
> 원본: llm-wiki-slides-bilingual.html · 난이도: ★★★(나중에)

## 한 줄 요약
문서를 던져주면 LLM이 마크다운 위키(지식 정리 노트)를 대신 써주고 계속 최신으로 유지해주는 작업 패턴이다.

## 이게 뭐예요?
보통 AI에게 문서를 주고 질문하면, AI는 **매번 처음부터** 문서를 뒤져서 답합니다(이 방식을 RAG라고 불러요). 아무것도 쌓이지 않죠. LLM 위키 패턴은 다릅니다. 새 자료가 들어올 때마다 AI가 읽고 정리해서 위키 페이지를 업데이트하니, 지식이 **적금처럼 복리로 쌓입니다**. 사람은 위키를 만들다가 정리(상호 참조, 요약 갱신)가 귀찮아서 포기하지만, AI는 지루해하지 않으니 그 잡일을 전부 맡길 수 있다는 게 핵심입니다.

## 핵심 정리
- 핵심 아이디어: 지식을 매번 다시 찾지 말고, **한 번 정리(컴파일)해서 계속 최신으로 유지**하라.
- 역할 분담: 사람은 자료를 고르고 질문만 한다. LLM이 요약·분류·연결·모순 정리 같은 잡일을 한다.
- 3개 층 구조:
  - `raw/`: 원본 자료(문서·논문·기사). LLM은 읽기만 하고 절대 수정 안 함.
  - `wiki/`: LLM이 생성한 마크다운 페이지들. 이 층은 LLM이 쓰고 사람은 읽는다.
  - 설정: `CLAUDE.md` 같은 파일에 위키의 규칙·구조를 적어둔다.
- 3가지 동사로 운영한다:
  - **Ingest(적재)**: 새 자료를 `raw/`에 넣으면 LLM이 읽고 관련 페이지 10~15개를 업데이트.
  - **Query(쿼리)**: 질문하면 페이지·표 등으로 답하고, 좋은 답은 다시 위키에 정리해 넣는다.
  - **Lint(린트)**: 주기적 점검. 모순, 오래된 내용, 끊어진 링크를 찾아 고친다.
- 특수 파일 2개: `index.md`(전체 페이지 목록 — 답할 때 먼저 읽는 카탈로그), `log.md`(작업 기록을 시간순으로 추가만 하는 일지).
- 결국 전부 git 저장소 안의 마크다운 파일일 뿐이라, 버전 관리가 공짜로 따라온다.
- 활용 예: 독서 노트, 연구 정리, 강의 노트, 팀 내부 위키, 여행 계획 등 "지식이 쌓이는 모든 곳".

## 따라해보기
1. 연습용 폴더 만들기:
   ```
   mkdir -p my-wiki/raw my-wiki/wiki
   ```
   → 원본 자료용 폴더와 위키용 폴더를 만든다.
2. `raw/`에 메모 하나 넣기:
   ```
   echo "오늘 배운 것: /clear는 대화만 지우고 파일은 안 지운다" > my-wiki/raw/note1.txt
   ```
   → 첫 원본 자료를 만든다.
3. 클로드 코드를 그 폴더에서 열고 부탁하기:
   ```
   raw/ 폴더의 자료를 읽고 wiki/ 폴더에 정리 페이지와 index.md를 만들어줘.
   ```
   → AI가 위키를 대신 써주는 흐름을 직접 체험한다.

## 주의할 점 / 자주 헷갈리는 것
- 이건 설치하는 프로그램이 아니라 **작업 방식(패턴)**이다. 정해진 도구 없이 폴더+마크다운으로 시작하면 된다.
- 원본(`raw/`)은 절대 수정하지 않는 게 규칙. 진실의 원천은 원본, 위키는 AI가 만든 정리본이다.
- RAG(매번 검색해서 답하기)와 다르다. 위키는 "검색"이 아니라 "축적"이다.
- 임베딩, 에이전트 자동화 같은 고급 구현은 나중에 배워요. 지금은 개념만 알면 충분.
