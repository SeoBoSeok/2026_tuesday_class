# 하네스(Harness) — 클로드 코드의 뼈대 이해하기
> 원본: claude_harness.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
클로드 코드 = 똑똑한 두뇌(모델) + 그 두뇌에게 손·눈·작업대를 달아주는 장비(하네스)이고, 하네스는 6개 층으로 이루어져 있습니다.

## 이게 뭐예요?
아무리 똑똑한 사람도 맨몸으로는 요리를 못 해요. 주방(작업 공간), 칼과 도마(도구), 레시피(규칙)가 있어야 하죠. 클로드라는 AI 모델은 이미 똑똑하지만, 실제로 파일을 읽고 명령을 실행하려면 "하네스"라는 주방 설비가 필요합니다. 클로드 코드가 바로 그 설비예요. 하네스는 도구 실행, 대화 기억 관리, 권한 확인, 실패 시 복구 같은 궂은일을 맡습니다. "모델보다 하네스가 진짜 어려운 부분"이라는 말이 있을 정도로 중요해요.

## 핵심 정리
- Agent(에이전트) = Model(Anthropic이 만든 두뇌) + Harness(여러분이 꾸미는 작업 환경)
- 하네스의 기본 동작: 사용자 입력 → 모델이 답 → 도구가 필요하면 실행 → 결과를 다시 모델에게 → 반복 (이걸 "에이전트 루프"라고 부름)
- 6층 구조: ① CLAUDE.md(프로젝트 규칙 메모) ② Skills(반복 작업 매뉴얼) ③ Hooks(자동 실행되는 강제 장치) ④ Subagents(별도 기억을 가진 보조 일꾼) ⑤ Agent Teams(여러 에이전트 협업) ⑥ Plugins(만든 것을 묶어 배포)
- Hooks가 중요한 이유: 말로 부탁하면 까먹을 수 있지만(비결정적), Hook은 기계적으로 무조건 실행됨(결정적)
- 도입 순서 추천: 1일차 CLAUDE.md만 → 1주차 Skills → 2주차 Hooks → 1달차 Subagents → 2달차 Plugins
- 원칙: 모든 걸 CLAUDE.md 한 곳에 욱여넣지 말 것. 실패를 겪은 뒤에 하네스를 보강할 것(미리 과설계 금지)
- MCP(외부 서비스 연결 통로)는 꼭 필요할 때만 — 대부분은 CLI 명령어로 충분 (자세한 건 나중에 배워요)

## 따라해보기
1. 내 프로젝트 폴더에 규칙 파일 만들기 — 클로드가 매번 읽는 메모장 생성
   ```
   echo "# 내 프로젝트\n- 한국어로 답해줘\n- 커밋 전에 꼭 테스트 실행" > CLAUDE.md
   ```
2. 클로드 코드 설정 폴더 구조 구경하기 — 어떤 파일들이 하네스를 구성하는지 확인
   ```
   ls -la ~/.claude
   ```

## 주의할 점 / 자주 헷갈리는 것
- "하네스가 클로드를 똑똑하게 만든다" X → 클로드는 이미 똑똑하고, 하네스는 일할 환경을 줄 뿐
- CLAUDE.md에 적은 건 "부탁"이라 어길 수 있음. 반드시 지켜야 할 건 Hooks로 강제하세요
- Subagents, Agent Teams는 초보 단계에선 몰라도 됩니다 — CLAUDE.md 하나부터 시작하세요
- 문제가 생기기 전에 미리 복잡하게 설정하는 것(과설계)이 가장 흔한 실수입니다
