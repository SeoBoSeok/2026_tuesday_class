# Opus 4.8 — 더 솔직해지고, 떼로 일하게 된 클로드
> 원본: claude_opus4.8.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
Opus 4.8은 "정직함"을 강화한 새 모델이고, 진짜 핵심은 클로드가 수백 명의 보조 클로드를 스스로 부려서 큰 작업을 동시에 처리하는 Dynamic Workflows 기능입니다.

## 이게 뭐예요?
한 명의 천재 요리사가 1000인분을 혼자 만들면 오래 걸리죠. 그런데 그 요리사가 직접 주방 보조 100명을 뽑고, 역할을 나눠주고, 완성된 음식을 검수까지 한다면? Opus 4.8의 Dynamic Workflows가 바로 그 모습이에요. 클로드가 작업을 쪼개고, 보조 에이전트(subagent)들을 동시에 돌리고, 결과를 검증해서 합칩니다. 게다가 이번 모델은 자기 코드의 결함을 숨기지 않고 먼저 말하는 "정직함"이 크게 좋아졌어요.

## 핵심 정리
- 정직함(honesty)이 핵심 기능: 모르면 모른다고 표시하고, 근거 없는 주장을 덜 함
- 이전 버전(Opus 4.7) 대비 자기 코드 결함을 말없이 넘어갈 확률이 4분의 1로 감소
- Dynamic Workflows: 클로드가 ① 작업 분석 → ② 지휘용 코드 작성 → ③ 보조 에이전트 수백 개 동시 실행 → ④ 결과 검증 → ⑤ 최종 보고
- 발상의 전환: "더 큰 기억력(context, 모델이 한 번에 기억하는 양)"보다 "일 잘 쪼개서 나눠주기"가 더 잘 통한다는 것
- `/effort` 명령으로 모델이 얼마나 깊게 생각할지 조절: low → medium → high → xhigh → max → ultracode
- ultracode = 최고 수준 추론(xhigh) + 자동 워크플로 지휘를 합친 클로드 코드 전용 설정

## 따라해보기
1. 클로드 코드 안에서 노력 단계 메뉴 열기 — 빠름↔똑똑함 슬라이더가 나타남
   ```
   /effort
   ```
2. 간단한 질문은 낮춰서 빠르게 — 비용과 속도 절약
   ```
   /effort low
   ```
3. 어려운 작업 전에 높이기 — 더 깊게 생각하고 필요하면 에이전트를 동원
   ```
   /effort high
   ```

## 주의할 점 / 자주 헷갈리는 것
- 항상 높은 effort가 좋은 게 아니에요 — 간단한 일에 max를 쓰면 느리고 비쌉니다
- max와 ultracode는 그 세션에서만 유지(세션 전용)되고, 다음에 켜면 원래대로 돌아갑니다
- 모델마다 쓸 수 있는 단계가 달라요 — 메뉴에 보이는 것만 선택 가능
- 보조 에이전트 수백 개가 돈다고 무조건 좋은 결과는 아니에요 — 작업 지시가 명확해야 효과가 있습니다
