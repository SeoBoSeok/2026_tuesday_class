# /init — 프로젝트를 Claude에게 소개하기
> 원본: claude_cmd_init.pdf · 난이도: ★☆☆(지금 필요)

## 한 줄 요약
`/init`은 Claude Code가 현재 프로젝트(폴더)를 스스로 둘러보고 이해하도록 만드는 "프로젝트 첫인사" 명령이다.

## 이게 뭐예요?
새 직원이 회사에 출근하면 먼저 사무실 구조와 업무 매뉴얼을 둘러보잖아요? `/init`은 Claude에게 그 "첫 출근 오리엔테이션"을 시키는 명령이에요. "Claude, 이 저장소(repository, 프로젝트 폴더)를 파악하고 준비해"라는 뜻이죠. 이걸 실행하면 Claude가 폴더 구조와 주요 파일을 훑어보고, 알게 된 내용을 CLAUDE.md라는 메모 파일로 남겨요. 이후 작업의 정확도가 눈에 띄게 좋아집니다.

## 핵심 정리
- `/init` = 현재 프로젝트에 맞게 Claude Code를 초기화 → "프로젝트 인식(awareness)"을 만들어줌
- 내부에서 하는 일: 저장소 구조 스캔 → 프로젝트 종류 감지(Python, Node, Go 등) → 중요 파일 확인(README.md, package.json, pyproject.toml, requirements.txt, Dockerfile, .env) → 기본 메모리 초기화
- `/init` 없이 쓰면 Claude는 "아무 정보 없이 허공에서 추론"하는 상태
- `/init`을 하면: 폴더 구조를 알고, 사용 언어 생태계를 이해하고, 더 정확한 코드 수정과 테스트 생성이 가능
- 실행 시점: 새 저장소를 만들 때, 프로젝트를 처음 clone(복제)했을 때, Claude가 프로젝트를 잘 모르는 것 같을 때, 크게 다른 branch(작업 갈래)로 옮겼을 때

## 따라해보기
1. `cd ~/내프로젝트폴더 && claude` — 프로젝트 폴더로 이동해 Claude Code 실행
2. `/init` — Claude가 프로젝트를 스캔하고 CLAUDE.md를 만들도록 함
3. `!cat CLAUDE.md` — 방금 만들어진 메모 파일 내용을 직접 확인

## 주의할 점 / 자주 헷갈리는 것
- `/init`은 **준비(컨텍스트)만** 해요. 패키지 설치, Docker 실행, 빌드, 배포는 **하지 않아요**. (인프라가 아니라 "이해"를 준비하는 것)
- 한 번 하면 영원히 끝이 아니에요. 프로젝트가 크게 바뀌면 다시 실행하거나 CLAUDE.md를 갱신하세요.
- CLAUDE.md는 그냥 텍스트 파일이라 직접 열어서 고쳐도 돼요. 잘못된 내용이 있으면 수정하세요.
- 빈 폴더에서 하면 얻는 게 거의 없어요. 코드나 README가 어느 정도 있는 상태에서 실행하는 게 좋아요.
